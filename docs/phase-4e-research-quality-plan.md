## 目标

在现有纸面交易、跨市场行情和证据门禁之上，先保证回测口径正确，再保证数据覆盖可解释、实验可复现，最后补齐研究比较和连续模拟验收。所有阶段继续保持 `paper_only=true`、`live_execution=false`、`can_submit_live=false`；美股策略观察在证据不足时保持 fail-closed。

## 优先级与验收标准

### P0：回测执行语义与换仓正确性

1. 已将新证据执行模型统一为 `next_trading_day_open-v1`，与 `quant_engine/backtest/matcher.py` 实际读取下一交易日 `open` 一致；旧的 `next_trading_day_close-v1` 仅作为可读取的 legacy 证据，不再由新回测生成。
2. 修正 `quant_engine/backtest/fund_engine.py` 的换仓顺序。实现先卖后买，并在现金、部分成交和反向代码排序下保持确定性。
3. 规模因子已拆分为真实 `log_market_cap`（需要点时市值字段）和显式 `log_market_cap_proxy`（成交额/换手率代理）；示例策略只能使用带 proxy 标记的后者。
4. 为上述两项添加回归：执行价取值、两基金反向换仓、费用后现金、订单顺序、最终持仓和剩余现金均需断言；不能只断言总收益。

验收：同一输入重复运行得到完全一致的订单序列、成交价、费用、现金和持仓；不存在因为先买后卖导致的可避免现金拒单。

### P0/P1：研究数据闭环

当前只读核对结果：`data/meta.db` 的 `stock_info=5556`，`fundamentals=0`，`index_components=0`；`data/raw/daily` 有 330 个 Parquet 文件、30 个不同代码。`data/market_a_share_5y/manifest.json` 记录 17,727 次请求：`error=1,262`、`ok=57`、`ok_fallback=16,105`、`skipped=303`。这些是请求状态，不等于证券或日期覆盖率。

施工顺序：

1. 按证券、日期、复权口径核验下载结果，补齐退市股票、历史股票池、停牌、涨跌停和公司行动所需覆盖。
2. 将下载结果校验、压缩、导入 `PriceStore`/回测实际读取路径，补回测前置检查；禁止以脚本结束或行情页证券总数代替研究覆盖证明。
3. 基本面按公告时点保存 point-in-time 版本；指数成分按生效区间保存；每个数据集记录来源、内容哈希、复权口径、日历和缺失/排除原因。
4. UI 展示实际证券数、日期范围、缺失率和排除原因，并让回测报告引用具体数据版本。

验收：指定股票池和区间能生成机器可读覆盖报告；缺失数据会在回测前明确阻断或列出排除清单；回测读取的文件与报告 manifest 一致。

### P1：实验可复现

1. `data_end` 必须来自实际可用数据截止日，而不是只复制请求结束日。
2. A 股回测绑定数据集内容哈希、历史股票池、复权口径、公司行动/交易日历和成本模型。
3. 策略指纹覆盖策略类、因子、回测引擎、撮合、成本依赖和参数快照；固定代码版本并支持按旧版本重跑。
4. `eligible_for_observation` 只表示证据字段完整，不表示策略已经有效或盈利。

验收：删除或替换当前数据后，按旧 manifest 仍能定位同一数据版本；同一代码、参数、数据和环境重复回测结果一致；策略或引擎任一依赖变化会使旧观察授权失效。

### P1：研究工作流

复用现有 `quant_engine/factor/evaluation.py` 的 IC、分层、相关性和 Fama–MacBeth 能力，扩展绩效页面/接口支持：参数与基准对比、收益/回撤/换手/费用、样本内外切分、滚动验证、参数敏感性和研究笔记（假设、结论、失败原因）。

验收：一次研究可保存为实验记录，至少能并排比较两组参数或基准；页面明确样本区间、数据版本和成本假设，不把单次绩效卡片称为验证结论。

### P2：成交与成本情景

保留现有简化模型的显式标签；增加可配置成交量参与率、部分成交、滑点情景、基金费用和到账延迟。费率只能来自已登记的模型或用户输入，不能捏造真实券商费率。报告同时展示毛收益、净收益和成本敏感性。

当前增量：基金回测已支持用户输入纸面 `fund_fee_rate`（默认 0），摘要记录 `fee_model` 与实际 `fee_rate`；现金不足时以 `partial/cash_limited` 记录可承受的部分成交；这些值是敏感性假设，不代表任何真实基金或券商费率。

验收：同一回测可切换至少两种明确命名的成本情景，订单和报告显示采用的情景；默认简化模型不会被 UI 描述为真实成交。

### P1/P2：连续模拟与发布基线

选取数据完整的小股票池和基金池，完成固定数据回测 → 样本外验证 → 7/30 天纸面观察 → 连续调度 → 人工中断/恢复 → 预期与实际对照。整理未提交改动、数据库、行情数据和结果目录，形成可追溯基线并演练 SQLite 备份恢复。

验收：能从基线重建服务；观察中断后计划、订单、持仓和事件不重复；发布记录包含测试输出、数据 manifest、浏览器链路和 paper-only 能力证明。不得用开发试验记录计算生产失败率。

# 个人量化研究系统：项目评估与施工路线

> 文档状态：2026-09-08 评估快照。此后的 500 股隔离研究、容量压力和数据库状态未回填；当前事实见 [`project-state-audit-2026-09-09.md`](project-state-audit-2026-09-09.md)，后续修改见 [`../PROGRESS.md`](../PROGRESS.md)。

记录：2026-09-08。依据当前代码、自动化测试和本机只读接口；未对公开数据源开展新的在线可用性认证。

## 判断

项目已有可继续迭代的完整基础，无需重建技术栈。最需要加强的是研究输入的可检查性、执行与估值语义，以及可复现的实验工作流。界面应围绕“选择数据 → 检查 → 实验 → 比较 → 观察”组织，而非只增加行情卡片。

| 领域 | 已存在的实现 | 实际限制 |
|---|---|---|
| 前端 | Vue3 工作台、行情详情、策略参数、回测与比较、模拟账户 | 原先缺少集中研究数据入口，错误和异步执行状态不够直观 |
| 日线研究 | Parquet、交易日历、内容哈希、覆盖门、事件复权 | 存在文件不等于完整历史；公司行动、成交量复权、历史交易规则证据仍需补齐 |
| 数据源 | 腾讯、AKShare 东财/新浪、东财基金 NAV、Yahoo 美股、新浪/Yahoo 黄金 | 公开源无本项目可验证 SLA；基金、美股、黄金与 A 股的可执行范围不同 |
| 回测 | A 股日线、基金 NAV、成本情景、协议预热、生命周期 | A 股默认股票池为起始日固定成分，不是逐日动态历史成分；成交量参与率和真实流动性尚未建模 |
| 研究质量 | 成本比较、内容证据、单个 COPA 固定研究流程 | 通用实验版本冻结、滚动样本外、多重检验、笔记与复跑还未产品化 |
| 交易 | 纸面订单、调度、观察和控制面 | 无真实券商适配；美股完整回测和自动策略观察仍阻断 |

## 本机检查

通过 `/api/v1/market/inventory/daily` 实测：13 个证券、455 个分区文件、27,278 个成功读取行、0 个文件读取异常；合计日期边界 2018-01-02 至 2026-08-31。

这些是**库存统计**，不能解释为每只证券在整个区间都有数据。该 Mac 的服务数据库中，策略实例、回测记录和基金 NAV 归档查询均为空；源码内置策略目录与数据库策略实例是两件事。

## 本轮交付

1. 新增研究数据中心：库存搜索、分页、选择证券、日线覆盖预检、缺失日期展开、报告导出、基金已归档版本和数据源能力说明。
2. 覆盖校验补齐 OHLC 正值、价格关系及成交量非负校验；零成交量平价行可保留为数据，但不应产生撮合。
3. 修复实际 Parquet 执行限制列被投影丢弃；涨跌停与 OHLC 同步复权；可选执行限制进入数据内容哈希。缺失限制仍是简化撮合假设，不能声称历史规则完整。
4. 修复组合加仓/减仓后的即时市值、超卖现金检查及分批 T+1 锁仓，避免旧可卖股因加仓全部锁住。
5. 回测中心补齐实验摘要、数据检查入口、状态刷新、取消、失败详情，以及未知收益与零收益的区别。
6. 收盘信号生成前更新组合估值，每个交易日仍只计一次日收益；取消默认指数股票池的 50 只静默截断，结果和 manifest 保留实际固定股票池及其选择方式。

本轮没有接入新的第三方提供商，也没有批量下载或重写用户行情。数据源页面整理的是现有能力，不把“配置过”标作“在线可用”。

## 下一阶段：按验收条件推进

### P0：历史数据与执行证据

- 建立逐证券的上市、退市、停牌、历史涨跌停与公司行动数据集。区分正常休市、上市前、退市后、停牌和真正丢失的数据。
- 统一原始成交价、策略调整价、股数与成交量复权口径，提供包含分红送转的现金/股数逐笔核算样本。
- 将历史股票池演变与证券生命周期用于事件引擎，不以当前成分或起始固定成分代替动态历史成分。
- 验收：含停牌、退市、拆送股、现金分红、成分调入调出的固定样本均有逐笔预期结果；缺乏证据的情景明确阻断或标明简化假设。

### P1：丰富数据源的可用范围

- 为现有采集链补统一任务状态、限频/重试、断点恢复、来源、复权口径、时间范围与导入前质量报告。
- 优先补历史财报公告版本、估值、市值、行业与指数历史成分；保留文件导入以适配用户已有授权数据。
- 新提供商按实际权限、历史深度、公司行动、退市覆盖、限频、价格与许可选择。接入前通过少量样本核对，不以提供商数量衡量质量。
- 验收：相同证券/日期支持来源差异报告；只有通过日期、单位、复权和代码校验的批次进入研究存储；失败批次不会假报成功。

### P1：实验管理

- 将数据集版本、策略及引擎依赖、参数、费用、基准、股票池和研究笔记组成不可变实验记录。
- 支持固定训练/验证/封存样本外切分、滚动验证、参数敏感性、多次实验对比及复跑。
- 验收：旧实验能定位旧数据和代码；同一输入经济结果一致；样本外打开状态可追踪，不能反复用作最终验证。

### P2：市场与撮合扩展

- 增加明确命名的流动性/成交量参与率、部分成交、滑点压力情景；不能用全天成交量改善开盘时决策而不说明前视口径。
- 美股先补交易日历、拆股/分红、币种、历史股票池及费用，再开放回测；黄金区分现货、ETF、期货连续合约，期货需要换月和保证金模型。
- 分钟级回测独立评估数据容量、交易时段、延迟与撮合，不把日线模型简单改频率后称为精确分钟回测。

### P2：研究界面与运维

- 总览转为研究进度与待处理数据问题；策略、数据集和实验之间提供明确跳转。
- 延续统一排版、状态提示、空态、窄屏表格和键盘操作；继续优化 ECharts 包体积。
- 建立固定研究集的定期回归、备份恢复与连续纸面观察验收。

## 兼容性与迁移

执行限制现在参与数据哈希，过去只按 OHLCV 生成的哈希可能变化。历史报告应保留；不能覆盖冻结证据伪装成原实验。需要使用新语义时，应新建研究版本并重跑相应基线。

后端通过全量测试仅代表测试所覆盖行为。上述尚未实现的数据与市场能力不能因此宣称完成。

## 已复现、待后续修复的问题

旧版 `server/services/paper_engine.py` 的 `SimulationAccount` 不保存分批锁仓，恢复仓位时将解锁日设为当前交易日。独立复核中，同日买入后重建该账户使可卖数量从 0 变成 100 股；其旧快照路径也允许同日重复记录。本轮修复的是回测内存组合，不能替代该旧链路的恢复验收。后续应持久化批次锁仓或限制同日重复执行，并与当前持久化纸面订单链路明确区分。

后续状态（2026-09-09）：上述 legacy 快照问题已修复。`paper_position` 保存 `unlock_date` 和未解锁批次；同日快照使用事务内替换并显式 flush，重启后仍按批次数量执行 T+1。旧数据库行没有批次元数据时，同日恢复采取保守锁定、较早快照按已过 T+1 处理。该修复不改变当前持久化 `PaperAccount/PaperLot` 主链路。
